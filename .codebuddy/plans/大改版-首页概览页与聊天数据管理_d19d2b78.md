## 产品概述
在现有「约刻」约课系统（Laravel + Blade，移动端优先）上做大改版：登录后进入新的首页，通过首页两大入口分别进入「约课聊天」与新增的「数据概览」；聊天助手新增 CRM 类指令，支持办卡、安排课时、报备会员消耗并自动更新数据。

## 核心功能

### 1. 首页与登录跳转
- 登录/注册成功后不再直达约课页，改为跳转首页；首页展示品牌与两个大入口按钮：「约课聊天」（进入现有 /appoints）与「数据概览」（进入 /overview）。
- /appoints 保留可直达（旧链接不失效）；聊天页顶栏增加返回首页/概览入口。

### 2. 数据概览页（/overview）
- 顶部大搜索框 + 范围选择：「学员 / 会员 / 教练」三者可选一，全部不选时为全局匹配；按姓名、手机号模糊搜索。
- 三大模块（学员/会员/教练），全局搜索时三组结果按模块分组展示。
- 学员：姓名、手机号、教练、已上课次数（非取消约课记录数，口径与聊天一致）、剩余课程次数（档案课时总数 − 已上课次，无档案不显示）。
- 会员：姓名、手机号、购卡类型（月卡/年卡/次卡）、月/年卡起止日期、次卡总次数、已使用次数、剩余次数或剩余天数（月/年卡按结束日期自动计算，支持过期标识）。
- 教练：姓名、上课次数、在教的学员列表（学员姓名可点击跳转学员详情）。
- 学员详情：点击学员行/学员姓名后展示档案字段与统计数据。

### 3. 聊天助手新增指令（自动更新数据）
- 办卡：「给某某会员办20次游泳卡，手机号xxx」→ 创建/续会员卡（次卡记总次数；月卡/年卡按起止日期，缺省按当前日期推算并默认期限）。
- 安排课程：「给学员A和B安排王教练，10次课」→ 批量给学员建档（姓名+可选手机号）、累加总课时、更新当前教练。
- 报备消耗：「某某会员用了一次 / 今天来游了」→ 该卡已使用次数 +1 并留使用记录；月/年卡剩余天数自动展示。

### 4. 范围与说明
- 学员与会员为两类独立的人；教练在教的即学员。
- 本次以 Seeder 造一批测试数据供页面演示；Excel 批量导入老数据留待后续版本（本期不做导入功能）。


## 技术栈
- 沿用现有栈：Laravel（PHP）+ MariaDB + Blade + 原生 JS/CSS，豆包 Ark API 做意图解析，移动端优先。
- 多租户隔离沿用现有模式：各表带 organization_code + OrganizationScope 全局 Scope + Model::creating 自动填充。

## 架构设计
### 模块划分与数据流
```mermaid
flowchart LR
    subgraph FE[Blade 页面]
        Home[首页 home] --> Appoints[约课聊天 /appoints]
        Home --> Overview[数据概览 /overview]
    end
    subgraph BE[后端]
        OC[OverviewController] --> OVS[OverviewService 聚合统计/搜索]
        CC[ChatController] --> DS[DoubaoService 意图解析]

```
- 概览读路径：/overview 页 → GET /api/overview/search（q + scope + focus_id）→ OverviewService 聚合查询返回学员/会员/教练分组列表。
- 聊天写路径：豆包新增三类 intent（办卡/安排课时/报备消耗）→ ChatController 分发到 CrmService 写库，继续沿用消息存档、Excel 联动（仅约课变动时）与前端轮询模式。

### 数据层设计（均仿 BookingRecord 的 Scope + creating 模式）
- `students`：name、phone(可空)、coach_name(当前教练)、lessons_total(总课时，安排课时时累加)、remark、organization_code；已上课次/剩余课时不落库，由 booking_records(student_name like) 聚合。
- `membership_cards`：member_name、phone、card_type(month/year/visits)、total_count(次卡)、start_at、end_at、used_count、status(active/expired)、note、organization_code；剩余次数=total−used，月/年卡剩余天数=end_at−today。
- `membership_usages`：card_id、used_at、note（报备消耗留痕，可选写入）。
- 教练不建主表：教练列表 = booking_records.coach_name ∪ students.coach_name 去重聚合；上课次数按 coach_name 统计非取消约课；在教列表 = students 中 coach_name 匹配。
- 新表均给 name/member_name 与 phone 建普通索引（当前数据量小，like '%q%' 全表可接受，不加复杂全文索引）。

### 概览后端
- OverviewService 输出统一结构：`{ q, scope, students:[...], members:[...含卡详情/剩余], coaches:[{name, lessons, teaching_students:[...]}] }`；scope=students/members/coaches 时只返回对应组，scope=all 三组全返；空关键词返回全量。
- 学员/会员详情用同一结构按 id 取单条（学员详情含档案+统计；会员详情含名下卡列表）。
- 控制器只做参数校验（q≤50 字符、scope 枚举校验），防注入用查询构造器参数绑定。

### 聊天扩展
- DoubaoService::parseBookingAction 的 system prompt 增加三类意图与中文示例、字段 schema、默认值规则（月/年卡默认今天起 1 月/1 年；次卡必须给次数；安排课时可为多个学员名）。
- ChatController：扩展本地预筛关键词（办卡/会员/卡/课时/安排/用了/游了 等）与 switch 分发（doCreateCard / doArrangeLessons / doUseCard），沿用现有异常包装与助手消息存档。
- CrmService：唯一写入口（事务内建档+累加课时；办卡冲突/重复名按手机号或姓名定位并提示，沿用 locateTarget 的多候选追问风格）。

## 实现要点
- 前端沿用现有原生 JS + 独立 css 文件 + `?v=filemtime` 防缓存模式；概览搜索输入做 250ms 节流与防抖，避免每个字符打接口。
- 聚合统计按名字 like 与既有约课口径一致；数据量小，所有概览查询一次完成、内存分组，避免 N+1。
- 组织隔离：所有新查询走全局 Scope，演示 Seeder 只写当前默认机构，避免跨机构泄漏。
- 不改动现有约课主链路与豆包超时/重试封装，避免回归；新意图失败同样走 RuntimeException 友好提示并存档。
- 实施前用现有 Excel/图片等 Job 路由注册位置核对新增接口放置（web.php 内 auth 组，跟随现状）。


## 设计风格
延续「约刻」现有移动端优先的清爽风格并整体升级为现代卡片式界面，主题色沿用品牌 Indigo（#4C6EF5）。

### 页面规划
**首页（1 屏）**：居中品牌区（logo 圆形渐变 + 名称「约刻」+ 副标），下方两张大入口卡片纵向排列，卡片含图标圆底、标题与说明文字与右箭头，点击跳转；弱化页脚版权。

**概览页（主）**：
- 顶部导航：左侧返回首页箭头 + 标题「数据概览」+ 右侧机构/用户徽标；sticky 顶部。
- 搜索区（sticky）：大号胶囊搜索框（放大镜图标 + placeholder「搜索姓名 / 手机号」），下方一排分段 chip：全部 / 学员 / 会员 / 教练（默认「全部」），选中高亮填充主题色，点选即限定模块、不选即全局。
- 分组列表区：scope=全部 时按「学员」「会员」「教练」三组依次渲染，组标题左侧圆点色块 + 名称 + 命中数；每组纵向卡片列表。学员卡：姓名+手机号、教练名、右侧「已上 X 次 / 剩余 Y 次」徽章。会员卡：姓名+手机号、卡类型彩色徽章（月卡/年卡/次卡），起止日期或总次数，已用/剩余用浅色进度条或徽章表达（月/年卡显示「剩 N 天」或灰色「已过期」）。教练卡：姓名 + 上课次数，在教列表以可点小标签呈现学员姓名。
- 空态：无结果时展示居中空态图标与文案。
- 学员详情：底部抽屉弹层，展示头像首字圆、姓名、手机号、教练、已上课次/剩余课时（进度条）与基础档案字段，右上角关闭。

### 交互与动效
卡片 hover/点击有轻微上浮阴影过渡；chip 切换 150ms 淡入；搜索清空按钮；输入防抖即时刷新；下拉刷新不做（数据量小）。
