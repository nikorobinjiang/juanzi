## 产品概述
为多机构约课系统增加机构认证码机制，并将旧机构数据合并到新机构，保证账号体系平稳过渡。

## 核心功能
- 旧数据迁移：将原 swim（游泳培训班）、ball（球类培训班）两个机构下的全部数据（用户账号、聊天记录、约课记录、生成图片）迁移归入网球馆A（tennis_a），旧账号改机构码后仍可用原密码登录
- 机构认证码：每个机构需 6 位字母数字认证码；机构首次被注册选择时由系统随机生成（首个用户可修改为自定义码）并持久化；此后注册该机构必须填写正确认证码才能注册成功
- 登录不受影响：登录仍只需 机构+用户名+密码，无需认证码
- 机构列表来源由配置文件切换为数据库表，机构可在运行期动态管理


## 技术栈
- 沿用现有 Laravel 11 + MySQL + Blade + 原生 JS 架构，不引入新框架
- 新增 `organizations` 表持久化机构与认证码，替代静态 config 文件

## 实施思路
### 数据层
- 新建迁移 `create_organizations_table`：`code`(varchar30, unique)、`name`、`auth_code`(varchar6, nullable，null=机构未初始化)、timestamps；迁移内直接插入 4 个机构种子数据（auth_code 全为 null），保证测试（RefreshDatabase）与生产一致，无需额外 seeder
- 新建迁移：四张业务表 `users/messages/booking_records/generated_images` 中 `organization_code IN ('swim','ball')` 全部 UPDATE 为 `'tennis_a'`（迁移内用 DB 语句执行，不依赖模型全局作用域，保证 CLI 上下文可用）
- 新建 `App\Models\Organization` 模型：**不加 OrganizationScope**（机构表是全机构清单，不能被当前登录用户过滤）；提供静态 `generateAuthCode()`——6 位字母数字，排除易混淆字符 0/O/1/I/l，统一大写

### 后端（AuthController + 路由）
- `showLogin`/`showRegister`：机构来源从 `config('organizations.list')` 改为查询 `Organization` 表，仍以 `$organizations`（code/name）变量传给视图，两个 Blade 下拉遍历代码零改动
- `orgCodes()` 改为 `Organization::pluck('code')->all()`，登录/注册的 `Rule::in` 校验逻辑不变
- 新增 guest 路由 `GET /organizations/{code}/status`：返回 `{initialized: bool, default_code: string|null}`；未初始化时 `default_code` 为系统临时生成的码（**不落库**，仅在用户提交注册时持久化，避免占位泄漏）
- `register()` 新增认证码逻辑：
  - 校验字段 `organization_auth_code`：required + 正则 `/^[A-Za-z0-9]{6}$/`，错误文案"请输入 6 位字母或数字的机构认证码"
  - DB 事务内 `lockForUpdate()` 锁机构行防并发（两个用户同时首次注册同一机构时，仅一人能写入，另一人回退到"已设置码比对"分支）
  - auth_code 为 null（首次）→ 以用户提交的码（strtoupper）写入并创建用户；已有值 → strtoupper 比对，不一致返回"机构认证码不正确"
  - 用户创建与认证码写入同事务，失败整体回滚

### 前端（注册页 + 顶栏）
- `register.blade.php`：机构下拉后新增认证码输入框（`name=organization_auth_code`）+ 动态提示区 + 引入 `asset('js/auth.js')`（沿用现有 asset+filemtime 版本号模式）
- 新建 `public/js/auth.js`：
  - 监听机构下拉 change，fetch `/organizations/{code}/status`
  - 未初始化 → 提示"该机构首次注册，系统已生成认证码：XXXXXX（可修改）"，输入框预填临时码且可编辑
  - 已初始化 → 提示"请输入该机构认证码"，输入框清空必填
  - 输入自动转大写；提交前本地校验 6 位字母数字
- `chat.blade.php` 顶栏 `$orgName`：从 `config('organizations.list')` 改为查 `Organization` 表
- 登录页不加认证码（已确认仅注册需要）
- `config/organizations.php` 加废弃注释保留文件，不再被读取

### 性能与可靠性
- status 接口为单行主键查询，注册认证码校验为单行锁，无性能瓶颈
- 并发首次注册用 `lockForUpdate` 行锁保证认证码唯一确定性，避免竞态写覆盖
- 认证码统一大写存储与比较，消除大小写歧义；生成排除易混淆字符降低输错率

### 测试与部署
- 更新 `tests/Feature/AuthOrganizationTest.php`：所有 swim/ball 用例改为新机构 code，注册用例补 `organization_auth_code` 字段；新增用例：首次注册写码成功、已初始化机构错码被拒、认证码大小写不敏感、登录不带认证码成功、机构 status 接口返回正确
- 服务器部署顺序：提交推送 → `php artisan migrate`（建表+种子+数据迁移）→ `php artisan config:clear && php artisan config:cache`

## 关键代码结构
```php
// app/Models/Organization.php（核心契约）
class Organization extends Model
{
    protected $fillable = ['code', 'name', 'auth_code'];

    /** 生成 6 位大写字母数字码，排除 0/O/1/I/l */
    public static function generateAuthCode(): string;

    /** 机构是否已初始化认证码 */
    public function isInitialized(): bool;
}
```

```php
// AuthController::register 认证码核心逻辑（示意）
// 1) 校验 organization_auth_code: required + regex:/^[A-Za-z0-9]{6}$/
// 2) DB::transaction 内 Organization::where('code',$code)->lockForUpdate() 锁行
// 3) $org->auth_code === null → 写入 strtoupper($input) 并创建用户（首次）
// 4) 已有值 → strtoupper 比对，不一致 → back()->withErrors(['organization_auth_code' => '机构认证码不正确'])
```
