## 用户需求
登录页（及注册页）的机构下拉选项需要调整：
- 新增三个机构：**杭州阿蓝网球**、**杭州奕林棋院**、**杭州燃乐体育健身**
- 去掉**网球馆B**

## 功能要点
- 登录/注册页机构下拉列表、页面顶栏机构显示均以 `organizations` 数据表为准（`config/organizations.php` 已废弃）
- 新增机构认证码初始为空（未初始化），首个注册用户负责初始化，与现有机构行为一致
- 删除"网球馆B"前必须检查其关联数据（用户/消息/约课/图片），有数据则中止删除，防止数据孤立与用户登录异常
- 通过迁移文件方式实现，保证部署到服务器后可统一执行


## 技术栈
- Laravel 迁移（数据库版本化），无新增依赖；沿用项目现有迁移命名规范 `YYYY_MM_DD_00000N_描述.php`

## 实现方案

### 1. 新建迁移文件
路径：`database/migrations/2026_08_29_000001_add_orgs_and_remove_tennis_b.php`

### up()：三新机构插入 + 安全删除 tennis_b
1. **插入新机构**：使用 `DB::table('organizations')->insertOrIgnore()`，幂等可重复执行（避免迁移中途失败重跑时报唯一键冲突）：
   - `alan_tennis` → 杭州阿蓝网球
   - `yilin_qiyuan` → 杭州奕林棋院
   - `ranle_fitness` → 杭州燃乐体育健身
   - 三者 `auth_code` 均为 null（未初始化），`created_at`/`updated_at` 用 `now()`
2. **删除 tennis_b 前的安全检查**：依次统计 `users`、`messages`、`booking_records`、`generated_images` 四张表中 `organization_code = 'tennis_b'` 的记录数：
   - 全部为 0 → `DB::table('organizations')->where('code', 'tennis_b')->delete()`
   - 任一 > 0 → 抛出 `RuntimeException`，错误信息列出各表计数，**中止迁移**（安全优先，绝不静默删除造成数据孤立）
3. 迁移逻辑全部包在事务中（`Schema` 无关的纯数据操作，用 `DB::transaction`），保证插入/删除原子性

### down()：反向恢复
1. 恢复 `tennis_b` 机构（`auth_code` 置 null；注释说明原认证码无法从迁移中恢复，如需要手动补）
2. 删除三个新机构（`whereIn('code', [...])->delete()`）

### 影响范围与边界
- 登录校验 `Rule::in($this->orgCodes())` 自动基于新表数据生效，无需改 AuthController
- `organizationList()` 按 id 排序，三个新机构排在列表末尾；视图零改动
- 删除操作仅影响 `organizations` 表，不动任何业务数据行

### 性能与可靠性
- 数据量小（机构行数 < 10，检查查询 4 次 count），无性能问题
- 迁移幂等设计 + 事务包裹 + 安全检查三重保障，服务器执行 `php artisan migrate` 失败可回滚

## 执行与验证
- 本地无 php 运行时，语法层面通过 Lint（read_lints）验证；实际执行在服务器
- 部署链路：本地提交代码 → GitHub SSH 推送 → 服务器 pull → `php artisan migrate` → 刷新登录页确认下拉
