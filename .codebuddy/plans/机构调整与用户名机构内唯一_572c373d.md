## 需求概述
本次包含两项数据库与账号体系改造，均为未部署状态，需合并执行：

### 1. 机构清单调整
- 登录/注册页机构下拉新增：**杭州阿蓝网球**、**杭州燃乐体育健身**（认证码初始为空，首个注册用户负责初始化）
- **棋院A（qi_yuan_a）显示名改为"杭州奕林棋院"**：内部 code 不变，原有账号/约课/聊天数据自然归属，零搬运
- 去掉新增"杭州奕林棋院"机构（与改名冲突）
- 删除**网球馆B**（tennis_b）：删除前检查 users/messages/booking_records/generated_images 四张业务表关联数据，有数据则中止迁移

### 2. 用户名机构内唯一
- 同一个机构下用户名唯一，不同机构允许重复用户名（如网球馆A 与 杭州奕林棋院 都可以有 xiaoming）
- 注册：用户名唯一性从全局改为"所选机构内唯一"
- 登录：按机构+用户名+密码精确匹配，跨机构同名互不干扰
- 登录/注册页表单、认证码机制、错误提示风格均保持不变

## 实现方案

### 1. 修改机构迁移 `database/migrations/2026_08_29_000001_add_orgs_and_remove_tennis_b.php`（已存在未部署，直接改）
- `NEW_ORGS` 常量：去掉 `yilin_qiyuan`，保留 `alan_tennis`（杭州阿蓝网球）、`ranle_fitness`（杭州燃乐体育健身）
- `up()` 新增：`DB::table('organizations')->where('code', 'qi_yuan_a')->update(['name' => '杭州奕林棋院'])`（幂等，改名可重复执行）
- `down()` 反向：`qi_yuan_a` 的 name 恢复为"棋院A"，删除两个新机构、恢复 tennis_b
- 保留原 tennis_b 安全删除逻辑（4 表计数检查 + RuntimeException 中止）与 DB::transaction 包裹

### 2. 新建索引迁移 `database/migrations/2026_08_29_000002_make_username_unique_per_organization.php`
- `up()`：
  1. 存量检查：`users` 表按 (organization_code, username) 分组计数 >1 的记录存在则抛异常中止（列出冲突机构/用户名）
  2. `dropUnique('users_username_unique')` 删除全局唯一索引
  3. `$table->unique(['organization_code', 'username'], 'users_org_username_unique')` 新增联合唯一索引
- `down()`：删联合索引、恢复全局唯一索引（注释说明跨机构同名数据会导致恢复失败）

### 3. 注册校验改造（`app/Http/Controllers/AuthController.php` register）
- 第 68 行 `'unique:users,username'` 改为 `Rule::unique('users', 'username')->where('organization_code', $request->input('organization_code'))`
- 报错文案"该用户名已被注册，请换一个"保留；数据库联合唯一索引兜底并发重复注册

### 4. 登录匹配改造（login）
- 定位用户：`User::where('username', ...)->where('organization_code', ...)->first()`，不存在或机构不匹配提示"用户名、密码或机构选择不正确"
- `Auth::attempt` 附加 `organization_code` 条件，杜绝跨机构同名误匹配
- 方法注释同步更新

### 5. 测试补充（`tests/Feature/AuthOrganizationTest.php`）
- 新增：跨机构同名注册成功（tennis_a 已有 xiaoming 后，xiaoming@tennis_b 注册成功并落库）
- 新增：跨机构同名登录隔离（各机构 xiaoming 用各自机构+密码登录成功；用错机构被拒）
- 现有用例（同机构同名报错、选错机构报错）语义不变，RefreshDatabase 自动应用新迁移，应继续通过

## 边界与可靠性
- 两迁移时间戳 000001 < 000002，服务器 `php artisan migrate` 按序执行；机构调整先于索引改造，互不冲突
- 迁移均含幂等插入/存量检查/事务三重保障，失败可回滚；数据量小（机构/用户行数有限），检查为 O(n) 分组聚合，无性能问题
- 登录失败提示保持模糊（不区分机构错/密码错），安全性不变
- 视图（login/register.blade.php）、路由零改动；登录下拉数据来自 organizations 表自动生效
