## 产品概述
修复线上 `/login` 访问 404 的问题，并完善未登录访问时的跳转体验：用户未登录访问业务页面时自动跳转到登录页，登录页提供「所属机构」下拉选择（机构列表来自 `config/organizations.php`），用户先选择培训机构再输入用户名密码登录。

## 核心功能
- 未登录访问 `/appoints`、`/generate` 等业务页面自动跳转 `/login`（现有 `redirectGuestsTo` 已实现，需在部署后生效）
- 登录页新增「所属机构」下拉选择：必选、默认选中第一个机构、选项来自机构配置文件
- 登录校验升级：机构必须在配置内、且所选机构必须与该用户名注册时所属机构一致（用户名保持全局唯一，机构选择用于防止用户选错机构登录后进错工作区）
- 修复 login 404：根因是账号系统全部改动尚未提交（git 未提交），服务器部署的是旧代码、没有 `/login` 路由；需提供部署排查清单（提交代码 → 服务器 migrate → 清缓存 → 伪静态/运行目录检查）


## 技术栈
- Laravel 12 + Blade 模板 + MySQL（完全复用现有技术栈，无新增依赖、无新迁移、无数据模型改动）
- 登录页复用现有 `public/css/auth.css` 样式，其中 `select.form-input` 已支持下拉框样式，无需新增样式

## 实施思路
404 根因已确认：本地代码（`routes/web.php` 的 `/login` 路由、`login.blade.php`、`AuthController`、`bootstrap/app.php` 的 `redirectGuestsTo`）全部正常，且 `bootstrap/cache` 无路由缓存；但 git status 显示本次账号系统改动均为未提交/未跟踪状态，服务器 nginx/宝塔 拉取部署的是旧代码，因此 `/login` 路由不存在返回 404。**代码侧只需补齐登录页机构选择，404 由部署最新代码解决**。

登录页机构选择采用「展示 + 校验」策略：用户名全局唯一（用户已确认不改为机构内唯一），登录时校验所选机构与用户所属机构一致，不一致给出明确错误提示，避免用户选错机构登录后看到错误机构的数据。

## 实现要点
1. **`AuthController::showLogin()`**：与 `showRegister()` 一致，向视图传 `'organizations' => config('organizations.list', [])`
2. **`AuthController::login()`**：
   - 校验规则新增 `organization_code`：`required` + `Rule::in($this->orgCodes())`，错误提示"请选择所属机构 / 请选择有效的机构"
   - 登录前先按 `username` 查用户（全局唯一），校验 `user->organization_code === 所选机构`，不匹配则 `back()->withErrors(['username' => '用户名、密码或机构选择不正确'])`
   - 匹配后再走 `Auth::attempt(['username', 'password'])`，成功 `redirect()->intended('/appoints')`
3. **`login.blade.php`**：在用户名输入框上方新增机构 `<select name="organization_code" required>`，遍历 `$organizations` 生成 `<option>`，用 `@selected(old('organization_code') === $org['code'])` 保持回显，默认选中第一项；复用 `form-group / form-label / form-input` 样式，`@error('organization_code')` 显示字段错误
4. **测试更新**（`tests/Feature/AuthOrganizationTest.php`）：
   - `test_login_and_logout()` 的 `post('/login', ...)` 增加 `'organization_code' => 'swim'`
   - 新增用例：机构不在配置内 → `assertSessionHasErrors('organization_code')`；所选机构与用户机构不一致 → `assertSessionHasErrors('username')` 且保持未登录
5. **README**：登录说明补充"登录时选择所属机构"；新增"部署到服务器"小节说明 404 排查清单

## 部署排查清单（交付给用户执行，非代码改动）
1. 本地 `git add` + `git commit` + `git push`（或整站上传），确保服务器代码包含 `/login` 路由与全部新文件
2. 服务器执行：`php artisan migrate`（新迁移建 username/organization_code 列并清空存量业务数据）、`php artisan route:list | grep login` 确认路由存在、`php artisan optimize:clear`
3. 宝塔检查：伪静态选择 Laravel 模板（`try_files $uri $uri/ /index.php?$query_string;`）、站点运行目录指向 `public/`、重启 PHP-FPM/nginx
4. 若部署后仍 404，优先检查 git 版本是否最新（`git log --oneline -3` 与本地一致）
